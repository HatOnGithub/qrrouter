## Changes

- Classify QR Router under Dolibarr's **Multi-modules tools** category.
- Store warehouse location definitions, assignments and label preferences in QR Router's service database. Binloc is no longer a dependency. An optional one-time importer copies existing Binloc locations before that module is disabled.
- Add warehouse location links and tabs, links from product and serial/lot pages, and direct QR links in Dolibarr's serial list.
- Generate random serials for every new tracked individual, with an optional product-owned prefix configured on the Dolibarr product card. Existing serial associations and container lot identities remain intact.
- Print the short/display name before the serial number. Move print rendering into TypeScript and creation/location rules into C#, keeping PHP focused on native Dolibarr integration.
- Prefill registration labels from the product display name, using `Container of {name}` for boxes while preserving manual overrides.
- Allow deletion of unassigned QR codes, with confirmation, print-batch cleanup and audit retention. Assigned items and pending operations remain protected.
- Add CSV inventory exports and validated imports for creating items, registering blank labels and updating metadata or locations. Imports provide a preview and per-row results, preserve completed rows after errors, and retain the existing native stock safeguards.

## Updating

Back up the Dolibarr database and QR Router service data together, resolve pending stock operations, and install the matching module and service packages. Keep the existing service configuration and data directory. Follow the [update guide](../updating.md).

Disable and re-enable QR Router once after installation to refresh its dependencies, hooks, tabs and product prefix field. Existing prefix values are retained. The service applies an EF Core data migration that preserves location label preferences; existing QR assignments and saved location codes remain stored.

If using Binloc, import its warehouse definitions and QR-associated lot locations through **Bins and locations > Import Binloc locations** before configuring those warehouses in QR Router. Verify the imported locations before disabling Binloc. Future location edits are managed in QR Router.

CSV instructions are in the [CSV guide](../user-guide/csv.md). Existing assigned quantities, warehouses and serial/lot identities are changed through the warehouse workflows.
