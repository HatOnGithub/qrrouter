## Changes

- Fix open warehouses being rejected as closed on Dolibarr 21.0.2. Stock validation now prefers the native `statut` property and supports `status` when only the newer property is available. The shared check covers creation, stock workflows, transfers, employee handoffs and synchronization recovery; missing or closed warehouses remain rejected.
- Add regression coverage for legacy and modern warehouse status properties, rejection of closed warehouses, and recovery of retained synchronization after reopening a warehouse.
- Run native API compatibility checks in CI against official Dolibarr 21.0.2, 22.0.5, 23.0.4 and 24.0.2 sources. Future versions require verification before support is claimed.
- Add a troubleshooting guide covering receipt-table installation, warehouse validation, pending synchronization, service connectivity and upgrade data preservation.

## Updating and recovering a pending operation

Install the matching module and service packages using the [update guide](../updating.md), preserving existing configuration and data. This release adds no database migrations. Updates from v0.3.6 or earlier still require the JSON-to-SQLite migration precautions in that guide.

If a stock action was retained after `Warehouse missing or closed`, verify that the intended warehouse exists and is open, install this fix, then select **Recover synchronization** after the original request has finished and at least 30 seconds have passed. Recovery uses the existing operation; do not submit the stock action again.

If `Native receipt table unavailable` appears, disable and re-enable QR Router in Dolibarr's module setup to run its table installer, retaining data and settings. See [Troubleshooting](../troubleshooting.md) if the error remains.
