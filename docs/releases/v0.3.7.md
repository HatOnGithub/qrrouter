## Updating from v0.3.6 or earlier

**This release migrates service inventory from JSON to SQLite.** Before updating, stop operator access and the old service, then back up the complete service data directory, external configuration, Dolibarr database and QR document directory together. Install the matching module and service from this release.

Keep the same absolute `AppSettings.DataDirectory` and, for Docker, the existing `/data` volume and Compose project identity. On first access to each entity, the new service applies Entity Framework Core migrations and imports its existing schema-2 `state.json` in a transaction. QR identities, associations, batches, history, loans and pending operations are preserved. Migration does not create Dolibarr stock movements. Invalid JSON is rejected rather than replaced with empty inventory.

The original JSON remains unchanged as a migration backup. **After migration, `state.sqlite3` is authoritative; the old JSON is no longer updated.** Do not run an older service against migrated data or delete the database to force another import. To roll back, restore coordinated pre-update backups. Back up the whole data directory with the service stopped, including any SQLite journal files.

Follow the [update guide](https://github.com/HatOnGithub/qrrouter/blob/v0.3.7/docs/updating.md) for backup, verification and rollback steps. Existing external API keys and configuration remain in use. No separate database server is needed.

## Changes

- Embedded SQLite persistence managed through Entity Framework Core, with an initial versioned migration and model snapshot for future schema changes.
- Indexed warehouse reads include current native warehouse observations, including arrivals and departures.
- Updates save changed records and append audit history in one transaction. Normal inventory requests omit private audit history; explicit service exports can still include it.
- Automatic JSON import retains the original file and supports retry after an invalid source is corrected.
- Migration tooling and development instructions, plus expanded concurrent-write, rollback, authorization and restart-recovery tests.
