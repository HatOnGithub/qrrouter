## Updating from v0.3.5-beta.1

Before replacing the service, follow the [update guide](https://github.com/HatOnGithub/qrrouter/blob/v0.3.6/docs/updating.md) and back up the service data, Dolibarr database and QR document directory together.

**Storage configuration is now required:** `AppSettings.DataDirectory` must be an absolute, writable path outside the service application directory. Earlier relative paths such as `data` prevent startup. Locate and copy existing data while the service is stopped before changing its path; the service does not move data automatically.

Standalone installations can keep their settings outside release files using `QRR_CONFIG_FILE`. Existing Docker Compose deployments retain their `/data` named volume and environment settings; keep the same Compose project and volume identity.

## Changes

- Inventory hides unassigned and consumed items by default. Use **Type > Unassigned** or **Status > Consumed** to show them; searching alone keeps them hidden.
- External service configuration and storage validation protect inventory when replacing application files. Upgrade tests verify saved entries, batches and pending stock operations survive an application-directory change.
- New update instructions cover backups, migration, verification and rollback.
- Project-wide MIT licensing is included in both module and service distributions.
- Removed unused PHP helpers, an obsolete test alias and generated logs; tightened Git and Docker exclusions.

## Downloads

- `module_qrrouter-v0.3.6.zip`: install through Dolibarr's external-module installer; includes the built interface.
- `qrrouter-service-v0.3.6.zip`: matching portable service; requires the .NET 10 ASP.NET Core Runtime.
- `SHA256SUMS`: SHA-256 checksums for both ZIPs.

Use the module and service from this same release. See the [installation guide](https://github.com/HatOnGithub/qrrouter/blob/v0.3.6/docs/installation.md) for a new installation.
